# WoW Live

A Windows app for Mythic+ keys, read live from the game's combat log (README.md).

- `backend/` is one Go module (`clients/` outside systems, `models/` types and interfaces, `service/` the rules, `controller/` the Gin API with swaggo annotations, `app/` the wiring, `cmd/` entry points). Run `gofmt`, `go vet ./...` and `go test ./...` there; after changing an endpoint or its types, run `swag init -g cmd/site/main.go -o docs --parseInternal`.
- `frontend/` is React + Vite + TypeScript: `api.ts` is the only file that knows URLs, and values the backend owns come from the API. Run `npm run lint`, `npm test` and `npm run build`. No Prettier config: single quotes, no semicolons, 120 columns, never reformat whole files.
- The app (`backend/cmd/app`, Wails v3, Windows only) is built with `bash backend/cmd/app/build.sh`. Before restarting a running copy, check the newest combat log for a key in progress. A copy started from Claude's shell writes its data into the Claude app's package folder, so let the owner start it.
- The rules' names live once in `mplus.toml` (M+) and `raid-rules.toml` (raid), the dungeon facts in `reference/mplus-dungeons.json` (written by `go run ./cmd/mplusref`) and the raid's boss mechanics in `reference/raid-bosses.json` (`go run ./cmd/raidref`); nothing hardcodes a guild, realm or character. A raid pull runs on the log tracker's per-fight run (`service/raid.go`), so deaths, defensives, meters, must-stops, dispels and the replay's track share the M+ code; its lanes and "Fix next pull" suggestions are `service/raid_review.go`.
- The game writes its combat log in batches as fights start and end (Nov 10: 2:45 of a boss fight in one write), and logs no end for a key the party left. So nothing is live inside a fight or while a party stands around before a key, and a silent log can be a long fight: `quietMS` and `LogTracker.Abandon` in `service/mplus.go`, which leaves a raid pull alone (a fight can outlast any silence).
- Changes go through a branch (`feat/…`, `fix/…`, `chore/…`) and a PR; commit, push and open it only when the owner says so. What each PR changed goes under `[Unreleased]` in CHANGELOG.md. The Store's MSIX builds only on a `v*` tag or by hand.
